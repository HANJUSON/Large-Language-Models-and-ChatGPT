# 거대언어모델과챗GPT — 최종 프로젝트 요구사항 명세

> **프로젝트명: 프롬프트 인젝션 탐지 모델의 표현 변형에 대한 견고성과 정상 입력 오탐 분석 및 개선**

- 문서 기준일: 2026-11-12
- 개정 내용: Claude Code의 2차 보완을 재검토했으며, 조교 데이터셋 밖의 공개 자료를 이용한 외부 Robustness 평가를 필수 범위에 추가했다. 데이터 사용·학습 예산·선택 기준·통계 비교·최종 평가 동결 규칙을 함께 명시한다.
- 상태: 계획 수립 단계. 이 문서는 구현·학습 완료 보고서가 아니다.
- 과제 주제: 조교가 제시한 Prompt Injection Dataset을 활용한 정상 프롬프트와 인젝션 프롬프트의 이진 분류
- 팀의 진행 방향: **3개 모델 파인튜닝 및 비교 → 취약점 분석 → 대표 모델 개선 → 원본·변형·외부 데이터 최종 검증 및 시연**
- 문서 구분: 아래 실험 설계와 완료 기준은 팀이 합의한 연구 계획이며 공식 채점표를 의미하지 않는다.

## 1. 목적과 연구 질문

주어진 데이터셋으로 탐지기를 학습하고, 표현이 바뀐 공격과 공격처럼 보이는 정상 입력에서 모델의 동작을 분석한다. 이어서 판정 임계값 조정과 데이터 증강의 효과를 분리해 검증한다.

| ID | 연구 질문 | 확인할 결과 |
| --- | --- | --- |
| RQ-01 | 같은 데이터로 파인튜닝한 세 모델의 탐지 성능과 자원 사용량은 어떻게 다른가? | 모델별 F1·탐지율·오탐률·학습 및 추론 비용 |
| RQ-02 | 공격 의도를 유지하면서 표현이나 주변 문맥을 바꾸면 탐지 성능이 유지되는가? | 변형 유형별 탐지율과 원문 대비 판정 변화 |
| RQ-03 | 공격 관련 단어가 포함된 정상적인 보안 질문·인용 문장을 공격과 구별하는가? | 어려운 정상 입력의 오탐률과 오류 사례 |
| RQ-04 | 임계값 조정과 데이터 증강은 탐지율·오탐률·원본 성능에 어떤 영향을 주는가? | A~D 조건의 비교 및 개선에 따른 이득과 손해 |
| RQ-05 | S-Labs 밖의 공개 자료에서도 탐지 성능과 정상 입력 오탐 제어가 유지되며, 내부 개선 효과가 전이되는가? | 출처별 성능·오류 유형·내부 대비 변화 및 외부 A~D 비교 |

## 2. 범위

### 2.1 필수 범위

1. 데이터 품질 점검과 공통 전처리 규칙 수립
2. BERT·RoBERTa·DeBERTa 계열 모델 각 1개 파인튜닝 및 비교
3. 표현 변형 공격과 어려운 정상 입력으로 구성된 추가 평가 사례 설계
4. 세 모델의 취약점 및 오탐 유형 분석
5. 대표 모델 1개 선정 후 임계값 조정·데이터 증강의 A~D 비교 실험
6. 개발에 사용하지 않은 원본·변형 자료에서 최종 평가
7. 외부 공개 데이터셋을 찾아 출처·레이블을 확인하고, 완성된 모델의 Robustness 평가
8. 결과 보고서·발표 자료·입력 및 변형 비교 시연 도구 작성

### 2.2 선택 범위

시간과 자원이 확보되면 탐지기를 실제 LLM 앞에 연결해 방어 전후의 **공격 목표 달성률과 정상 작업 성공률**을 측정한다. 보호 대상 LLM, 작업, 공격 목표와 성공 판정 기준은 별도로 정의한다. 분류 F1과 실제 방어 효과는 구분해 보고한다.

선택 실험의 수행 여부는 필수 범위의 완료 판단에 포함하지 않는다.

행 수는 원본 저장본 기준이다. 품질 점검 후 실제 사용한 행 수와 제외 사유를 따로 기록한다.

선택 기준으로 사용하는 `validation_clean`은 원본 validation에서 원본 train과 완전 중복인 문장을 제외한 고정 목록이다. 학습용 증강 사례가 이 목록과 겹치면 증강 사례를 제외해 목록을 유지한다. 같은 제외 규칙을 세 모델과 A~D 조건에 공통으로 적용한다.

**중복 판정 키와 모델 입력의 구분:**

| 구분 | 규칙 | 용도 |
| --- | --- | --- |
| 완전 중복 키 | 원본 `text` 문자열 그대로 비교 | 학습 데이터 중복 제거, `validation_clean`·중복 제외 test 생성 등 **자동 중복 제외의 기본 기준** |
| 정규화 키 | NFKC → 앞뒤 공백 제거 및 연속 공백을 공백 1개로 축약 → casefold | 완전 중복은 아니지만 사실상 같은 문장의 후보 탐지. 개수를 따로 기록하고 DATA-06의 유사 문장 검수 후보로 넘긴다. 정규화 키 일치만으로 자동 제외하지 않는다. |
| 모델 입력 | 원본 `text`를 변경 없이 각 모델의 공식 토크나이저에 입력 | 학습·평가·시연. 위 정규화는 모델 입력에 적용하지 않는다. BERT-base-uncased의 소문자화는 토크나이저 내부 동작으로 기록한다. |

정규화 키 일치 사례를 유사 문장 검수에서 제외하기로 결정하면, 그 결정과 목록을 학습 전에 기록하고 모든 모델·조건에 동일하게 적용한다.

### 3.2 품질 점검 및 분할 관리

| ID | 요구사항 | 확인 기준 |
| --- | --- | --- |
| DATA-01 | 원본 CSV를 보존하고 처리된 데이터와 처리 이력을 구분한다. | 데이터 revision·처리 규칙·처리 전후 행 수 기록 |
| DATA-02 | 빈 입력, 레이블 범위, 분할 내 중복, 같은 문장의 상충 레이블, 분할 간 중복을 점검한다. | 점검 결과와 제외·수정 사유 기록 |
| DATA-03 | 제공된 분할과 원본 파일을 유지한다. 정제된 학습 목록 및 중복 제외 평가 목록은 공통 규칙으로 별도 생성한다. 원본 test 전체 결과도 함께 보존한다. | 모델별 공통 데이터 목록과 제외 사유 기록 |
| DATA-04 | 전처리·임계값·대표 모델·증강 방법은 개발 데이터에서 결정한다. | test 결과를 사용한 설정 선택 또는 추가 학습 없음 |
| DATA-05 | 분할 간 중복을 식별하고 전체 validation과 `validation_clean` 성능을 병행 보고한다. 최종 단계에는 전체 test와 학습 데이터 중복 제외 test(`test_clean`)를 병행 보고한다. `test_clean`은 증강 데이터 동결 후, 모든 비교 조건의 학습 데이터(정제 train ∪ 증강 사례) 합집합과 완전 중복 키가 일치하는 test 행을 제외해 한 번 고정한다. | train–validation·train–test·validation–test 중복 수와 공통 평가 목록 |
| DATA-06 | 분할 간 완전 중복 및 유사 문장을 점검한 방법과 처리 결과를 기록한다. | 점검 기준, 후보 수, 검수 및 처리 이력 |

2026-11-12에 로컬 train·validation을 재점검한 결과는 다음과 같다. 아래 수치는 처리 전 상태이며 정제 완료를 의미하지 않는다. 정규화 키 기준 수치와 train–test·validation–test 중복은 아직 기록되지 않았으므로 1단계에서 추가한다.

| 점검 항목 | 확인 결과 |
| --- | ---: |
| train의 동일 문장 중복 추가 행 수 | 38행 |
| train의 동일 문장에 서로 다른 레이블이 붙은 경우 | 1개 문장 |
| train에도 존재하는 validation 문장 | 4개 문장 |

학습 데이터의 동일 문장(완전 중복 키 기준)·동일 레이블 중복은 1건을 남기는 것을 기본으로 한다. 상충 레이블은 사람이 검수하고, 정답을 명확히 정할 수 없으면 해당 문장 그룹을 학습에서 제외한다. 처리 이력을 보존하고, 유사 문장 점검 방법과 기준은 학습 전에 기록한다.

**test 사용 절차:** 개발 중에는 자동 중복·유사 문장 점검을 통해 중복 ID·개수와 필요한 검수 결과를 기록할 수 있으나, 이를 개별 사례 분석이나 모델·생성 규칙의 설계 재료로 사용하지 않는다. test 원문 열람은 아래 순서로만 진행한다.

1. **설계 동결(동결 1):** 데이터 처리 규칙, 세 모델과 대표 모델의 체크포인트, seed별 임계값, 증강 데이터, `test_clean` 목록, 평가 사례의 생성기·템플릿·프롬프트 버전, 조건별·레이블별 목표 원문 수, 추출 seed, 제외 기준과 대체 규칙을 기록하고 버전을 고정한다.
2. **추출:** 추출 후보는 `test_clean`이다. 추출 seed로 레이블별 후보 순서를 한 번 무작위로 섞고, 평가 조건 순서(ROB-01 → ROB-02 → ROB-03)대로 앞에서부터 목표 수만큼 겹치지 않게 배정한다. 사람이 원문을 골라 바꾸지 않는다.
3. **변형·검수:** 동결된 생성 규칙으로 변형하고 의미·레이블·길이 조건만 검수한다. 검수에서 제외한 원문은 같은 레이블 후보 순서의 다음 미배정 원문으로 대체하며, 제외 사유와 대체 이력을 기록한다. 변형 결과가 학습 데이터와 완전 중복 키로 일치해도 제외·대체한다.
4. **목록 동결(동결 2):** 검수를 마친 최종 평가 목록과 실제 수량을 고정한 뒤 예측을 실행한다.
5. **분석:** test의 예측·오류 분석은 최종 평가 실행 후에 수행한다.

최종 평가용 텍스트를 본 뒤에는 모델·임계값·학습용 증강 방법을 다시 조정하지 않는다. ROB-04처럼 test 원문에서 파생하지 않고 새로 작성하는 최종 평가 사례도 동결 1 이전에 최종 평가용으로 배정하고, 동결 2와 같은 시점에 목록을 고정한다. 조교의 공식 test 사용 규칙이 확인되면 그 규칙을 우선 적용하고 절차 변경을 기록한다.

| DATA-11 | 학습용 증강에는 놓치기 쉬운 공격과 공격처럼 보이는 정상 입력을 모두 포함한다. | 증강 유형별·레이블별 수량 기록 |
| DATA-12 | 개발용·최종 평가용 문장을 학습용으로 옮기지 않는다. 팀이 생성하는 추가 최종 평가 사례는 증강과 같은 유형의 새 사례와 증강에서 보류한 생성 방식의 사례를 나눠 구성한다. 생성·검수 규칙은 test 원문 추출 전에 동결한다. | 용도별 생성 자료 목록과 두 평가군의 결과 |

같은 변형 연산을 사용한 새 원문 평가는 해당 유형 안에서의 개선을 확인하는 실험으로 유효하다. 이를 새로운 생성 방식에 대한 일반화와 구분하기 위해, 증강에 사용하지 않을 생성 방식 또는 변형 조합을 최소 1개 사전에 지정한다. 보류군은 원문에서 파생하는 조건이면 해당 조건에 배정된 같은 원문에 적용해, 추가 원문 없이 같은 유형 평가군과 원문 그룹 단위로 짝지어 비교한다. 이 보류군이 원본 데이터나 사전학습에도 전혀 없었던 유형이라고 주장하지 않는다.

### 3.4 외부 데이터셋을 이용한 Robustness 평가

조교가 제시한 데이터셋과 출처가 다른 공개 자료에서 **출처·문맥·레이블 분포 변화에 대한 일반화**를 평가한다. 기존 ROB-01~04의 표현 변형 실험과 구분되는 필수 평가다. 가중치 학습에는 S-Labs의 train 및 그 학습용 증강 자료를, 모델·임계값 선택에는 validation_clean을 사용한다. 외부 자료는 완성된 모델의 최종 평가에 사용한다.

후보 조사는 2026-11-12에 공개 데이터 카드·공식 저장소를 기준으로 수행했다. 아래 행 수는 후보 원본의 안내 수치이며 실제 채택·영어 선별·중복 제거 후 수량은 별도로 고정한다. 이 문서 작성 단계에서는 외부 데이터를 내려받아 모델을 평가한 것이 아니다.

| 후보 | 평가 역할과 원본 구성 | 적용 계획 |
| --- | --- | --- |
| [deepset/prompt-injections](https://huggingface.co/datasets/deepset/prompt-injections) | `text`·`label` 형식의 공격·정상 이진 분류 자료. 공개 분할은 train 546행·test 116행, 총 662행 | 일반 분류 성능의 외부 평가 우선 후보. 영어 및 레이블 대응을 확인하고 채택 분할을 동결한다. 외부 파일명이 train이어도 이 프로젝트에서는 평가 전용으로 사용한다. 원본 분할별 결과도 기록한다. |

| [PINT](https://github.com/CheckPointSW/pint-benchmark) | 공격·정상 및 다국어·긴 문맥을 포함하는 탐지 벤치마크 | 확장 후보. 공식 노트북은 전체 데이터의 비공개 배포 및 연구 목적 접근 신청을 안내하므로, 공개 예제 파일을 전체 벤치마크로 취급하지 않는다. 접근이 확보되면 영어 부분부터 검토한다. |
| [Microsoft BIPIA](https://github.com/microsoft/BIPIA) | 외부 문서·이메일 등에 포함된 간접 인젝션을 평가하는 벤치마크 | 확장 후보. 문장 분류로의 변환, 정상 대응 문맥, 원본별 이용 조건을 먼저 정한다. 탐지 성능과 원래 벤치마크의 LLM 공격 성공률을 구분한다. |

기본 목표는 **공격·정상 양쪽을 포함하는 공개 출처 1개 이상과 어려운 정상 입력을 제공하는 공개 출처 1개 이상**을 최종 평가에 채택하는 것이다. 우선 후보는 deepset과 NotInject이며, 실제 채택은 모델 예측을 보기 전에 접근성·레이블 의미·이용 조건·중복 점검으로 결정한다. 부적합한 후보는 예측 성능과 무관한 사유를 기록해 동등한 공개 자료로 대체한다.

이용 조건은 채택할 revision의 데이터 카드와 원본 조건을 함께 기록한다. NotInject 데이터 카드는 MIT를 표시한다. deepset의 [현재 원본 README](https://huggingface.co/datasets/deepset/prompt-injections/raw/main/README.md)는 상위 license에 Apache-2.0, dataset_info 내부에 CC-BY-4.0을 병기하므로 사용 조건과 필요한 출처 표시를 확인한 뒤 최종 채택한다. PINT 접근 제한은 [공식 평가 노트북](https://github.com/CheckPointSW/pint-benchmark/blob/main/benchmark/pint-benchmark.ipynb)에 근거한다.

**외부 자료 동결 절차:** 동결 1에서 채택 출처·revision·채택 분할·레이블 대응·언어 선별·중복·입력 길이·선별/추출 규칙을 고정한다. 그 뒤 정해진 규칙으로 변환·검수하고 동결 2에서 실제 평가 목록과 수량을 고정한다. 스키마·접근성·원본 레이블 설명의 사전 조사는 허용하지만 개별 외부 사례에 맞춘 모델·증강·임계값 조정은 하지 않는다. 기존 50개 목표는 팀이 생성하는 ROB 사례에 적용하며, 외부 자료는 채택한 공개 분할의 적격 사례 전체를 평가하는 것을 기본으로 한다. 자원상 표집하면 모델 점수를 보지 않은 상태에서 출처·레이블·범주별 고정 seed로 표집하고 분포와 제외 사유를 기록한다.

외부 원문은 모델 입력 길이 때문에 선별 제외하지 않는다. 256토큰의 공통 입력 규칙으로 전체를 평가하고, 잘림이 없는 공통 부분집합 결과와 잘림 비율을 보조 보고한다. 후보 자료의 고유 레이블과 문맥을 보존하며, 긴 입력·다국어·간접 인젝션의 성능 변화를 모두 같은 원인의 실패로 해석하지 않는다.

출처가 다르다는 사실만으로 S-Labs나 사전학습과 완전히 독립적임을 보장하지 않는다. 출처 추적·중복 점검으로 확인한 범위와 확인할 수 없는 범위를 구분한다. 외부 평가 오류를 다음 학습의 재료로 사용하면 해당 자료를 개발 자료로 재분류하고, 후속 주장을 검증할 새로운 미사용 평가 자료를 확보한다.

### 4.2 학습 환경 및 초기 설정

- GPU: 팀이 사용할 NVIDIA GeForce RTX 5060, VRAM 8GB

| EXP-02 | 정상 입력을 공격으로 판단한 FP와 공격을 정상으로 판단한 FN을 나누어 분석한다. | 오류 사례 목록과 유형별 집계 |
| EXP-03 | 모델별로 3개 seed 중 2개 이상에서 틀린 문장을 해당 모델의 오류 사례로 집계하고, 세 모델의 공통·개별 오류를 비교한다. | 집계 규칙이 일치하는 오류 목록 |
| EXP-04 | 기본 임계값 0.5에서 `validation_clean`의 3-seed 평균 F1이 가장 높은 모델 계열을 선정한다. 동률(소수 넷째 자리 반올림 값이 같음)이면 평균 FPR, 같은 측정 조건의 평균 추론 시간이 낮은 순으로 정한다. 개발용 추가 평가 사례 결과는 선정 기준에 넣지 않고 함께 보고한다. | 최종 평가 전에 고정된 대표 모델과 선정 근거 |

### 5.2 추가 평가 조건

세 모델 모두 같은 개발용 추가 평가 사례에서 비교한다. 정상 입력을 포함할 수 있는 변형에는 정상 대응 사례도 마련한다.

| ID | 평가 조건 | 확인할 문제 | 주요 결과 |
| --- | --- | --- | --- |
| ROB-01 | 대소문자 / 공백 / 철자·문자 치환을 각각 평가 | 표면 형태가 바뀌어도 판별을 유지하는가? | 하위 유형별 성능과 토크나이저 정규화 영향 |
| ROB-02 | 같은 의도를 다른 표현으로 작성 | 익숙한 표현을 벗어나도 판별하는가? | 탐지율·오탐률 변화 |
| ROB-03 | 공격 앞뒤에 정상 문맥 추가, 정상 입력에도 대응 문맥 구성 | 정상 내용 사이의 공격을 탐지하는가? | 공격 탐지율·정상 오탐률, 위치·길이에 따른 실패 사례 |
| ROB-04 | 보안 교육·연구·인용 목적의 정상 입력 | 공격 관련 단어만 보고 오탐하는가? | 정상 입력 오탐률 |

기본 목표는 개발용·최종용 각각 평가 조건별·레이블별 **독립 원문 50개**이며, 100개는 확장 목표다. ROB-01은 같은 원문 50개에 세 하위 유형을 각각 적용해 하위 유형별로 짝지은 비교가 가능하게 하고, 하위 유형별 수량을 기록한다. ROB-04는 정상 사례만 구성한다. 같은 원문의 여러 변형을 독립 원문 수에 중복 산입하지 않는다. 개발용 원문은 `validation_clean`에서 같은 추출 seed와 배정 방식으로 고르며, 원문 그룹 ID를 유지한다. 보류한 생성 방식 평가군의 수량도 따로 기록한다.

수량은 두 단계로 구분한다. **목표 수량**과 추출·생성·검수·대체 규칙은 test 원문 추출 전(동결 1)에 고정하고, **최종 검수 수량**은 검수와 대체를 마친 뒤(동결 2)에 확정해 기록한다. 대체 후에도 목표에 미달한 조건은 실제 수량과 이유를 명시하고 탐색적 결과로 보고한다.

ROB-03의 핵심 비교 사례는 특수 토큰을 포함해 세 토크나이저 모두에서 256토큰 이내이며 공격 구간이 완전히 남도록 구성한다. 길이 조건 불충족으로 제외·대체한 수량을 기록한다. 긴 입력 실험을 추가하면 잘림 여부와 공격 구간 손실을 별도 집계한다. 원본 전체 test는 기존 입력 길이 규칙으로 평가하고 잘림 비율을 함께 보고한다.

원본 train에 이미 포함된 난독화 패턴과 새로 추가한 패턴을 구분해 기록한다. 특정 변형에서 성능이 하락할 것이라고 미리 결론 내리지 않고, 변화가 없거나 향상된 결과도 보고한다.

### 5.3 대표 모델의 개선 및 A~D 비교

개선 방법은 다음 두 가지로 정한다.

1. **임계값 조정:** 체크포인트를 먼저 확정한 뒤 각 seed에서 `validation_clean`만으로 임계값을 선택한다. 후보는 0.00~1.00, 간격 0.01로 고정하고, 후보 내 인젝션 F1 최대 → FPR 최소 → 더 높은 임계값 순으로 선택한다. 판정 규칙은 인젝션 점수가 임계값 이상이면 공격이다. B·D에 같은 규칙을 적용하고 seed별 임계값을 저장한다. 파생 개발 평가 사례는 임계값 선택에 사용하지 않는다.
2. **데이터 증강:** 개발 단계에서 확인한 취약점을 바탕으로 train에 추가할 공격·정상 사례를 만든다. 개발용 평가 사례의 문장을 학습에 옮기지 않는다.

| 조건 | 학습 데이터 | 판정 임계값 | 분리해 확인할 효과 |
| --- | --- | --- | --- |
| A | 원본 | 기본값 `0.5` | 개선 전 기준 |
| B | 원본 | `validation_clean`에서 seed별 조정 | 임계값 조정 효과 |
| C | 원본 + 증강 사례 | 기본값 `0.5` | 데이터 증강 효과 |
| D | 원본 + 증강 사례 | `validation_clean`에서 seed별 조정 | 두 방법의 결합 효과 |

| ID | 요구사항 | 확인 기준 |
| --- | --- | --- |
| IMP-01 | 각 seed에서 A·B는 같은 학습 체크포인트를, C·D는 같은 학습 체크포인트를 사용한다. A는 2단계에서 학습한 대표 모델의 seed별 실행을 다시 학습하지 않고 그대로 사용한다. | 임계값 외에는 각각 동일한 모델 |
| IMP-02 | A와 C는 같은 사전학습 체크포인트에서 새로 학습한다. 원본 train 3 epoch에 해당하는 총 update N, 유효 배치 크기, optimizer·학습률 스케줄·seed를 맞춘다. C는 A의 파인튜닝 결과에서 이어 학습하지 않는다. | 동일 총 학습 예산과 별도 학습 시작 기록 |
| IMP-03 | A와 C에 같은 update 평가 시점과 `validation_clean`·임계값 0.5의 체크포인트 선택 규칙을 적용한다. 선택된 step은 달라도 되며, 총 예산과 선택 기회를 맞춘다. | 총 예산·평가 횟수·선택 step 기록 |
| IMP-04 | 개선 실험도 공통 seed 3개로 반복하고 실행별 결과와 평균·표준편차를 보고한다. | A~D 비교표 |

validation은 선택·설계에 사용하는 개발 자료이므로 개발 결과임을 표에 표시한다. 최종 성능은 test와 최종 추가 평가 사례에서 별도로 보고한다. 공통 update 수는 학습 예산을 통제하기 위한 기준이며, 토큰 수·실행 시간·연산량까지 동일함을 의미하지 않는다.

### 5.4 완성된 모델의 외부 데이터 Robustness 평가

세 기본 파인튜닝 모델과 대표 모델의 A~D 설정을 동결한 뒤, 3.4에서 채택한 외부 자료에 그대로 적용한다. 외부 평가 자체로 추가 파인튜닝 모델을 만들지 않으므로 본실험 학습 횟수 12회는 유지된다.

1. **출처 변화:** 공격·정상 모두 있는 외부 출처에서 F1·Precision·Recall·FPR·ROC-AUC를 측정한다.
2. **정상 입력 오탐:** NotInject와 같은 정상 전용 자료에서는 FPR과 범주별 오탐 수를 측정한다. 공격 탐지율·ROC-AUC를 산출하거나 다른 공격 자료와 임의로 섞어 F1을 만들지 않는다.
3. **개선 효과 전이:** 같은 외부 사례에서 A→B, A→C, A→D의 지표 차이를 비교해 내부 개선이 외부 자료에서도 유지되는지 확인한다. 기존 원문 그룹 단위 짝지은 bootstrap을 적용한다.
4. **내부·외부 차이:** S-Labs `test_clean`과 외부 중복 제외 목록의 지표를 출처별로 나란히 제시한다. F1 차이는 레이블 비율의 영향도 받으므로 Recall·FPR·범주별 결과와 함께 해석한다. 서로 다른 데이터셋의 행을 짝지은 표본으로 취급하지 않는다.

외부 결과로 대표 모델이나 최종 조건을 재선택하지 않는다. 원본·변형·외부 자료에서 성능이 다른 이유를 오류 유형·길이·언어·레이블 정책으로 분석하고, 유지·향상·하락한 결과를 모두 보고한다.

## 6. 평가 지표와 최종 검증

### 6.1 필수 지표

| 지표 | 정의 또는 측정 기준 |
| --- | --- |
| F1 | 인젝션을 양성 클래스 `1`로 둔 Precision·Recall의 조화평균. 계산식은 `2TP / (2TP + FP + FN)`으로 고정한다. 공격 정답이 있는 셋에서 공격 판정이 하나도 없으면 0이다 |
| Precision | 공격으로 판정한 사례 중 실제 공격의 비율: `TP / (TP + FP)` |
| Recall / 공격 탐지율 | 실제 공격 중 탐지한 비율: `TP / (TP + FN)` |
| 정상 입력 오탐률(FPR) | 실제 정상 입력 중 공격으로 오판한 비율: `FP / (FP + TN)` |
| 혼동행렬 | TN·FP·FN·TP 및 평가 사례 수 |
| ROC-AUC | 임계값과 분리해 평가하는 인젝션 점수의 순위 판별 성능(보조 지표), 두 레이블이 모두 있을 때만 보고 |
| 조건 간 차이의 95% 신뢰구간 | 같은 원문 그룹을 함께 재표집하는 짝지은 bootstrap, 2,000회·초기 seed 314159, 백분위 2.5%·97.5% |
| 출처별 성능 변화 | 원본·외부 데이터셋별 F1·Recall·FPR과 레이블 비율·수량을 나란히 보고. 같은 정의의 지표 차이는 %p로 제시하고, 서로 다른 원문의 짝지은 비교로 계산하지 않음 |
| 변형 전후 판정 변화율 | 같은 원문·변형 쌍 중 원문과 변형의 예측 레이블이 다른 쌍의 비율. seed별로 계산해 평균한다. 유형별 성능 차이와 함께 보고 |
| 표준편차 | 3개 seed 결과의 표본 표준편차(n−1) |
| 학습 시간 | 공통 측정 구간을 정한 뒤 실행별 기록 |
| 최대 GPU 메모리 | 학습 실행별 최대 사용량, 측정 방법 포함 |
| 추론 시간 | 같은 입력과 배치 조건에서 측정, 워밍업·반복 횟수·토큰화 포함 여부 기록 |

양쪽 레이블이 모두 있는 평가셋에서는 F1·Precision·Recall·FPR·ROC-AUC를 보고한다. 공격만 있는 하위셋은 Recall을, 정상만 있는 하위셋은 FPR을 보고하고, 해당 레이블이 없어 정의되지 않는 지표는 계산하지 않는다. 분모 0 처리 규칙은 모든 지표·평가셋·bootstrap 표본에 같게 적용한다.

- Precision(`TP + FP = 0`), Recall(`TP + FN = 0`), FPR(`FP + TN = 0`), F1(`2TP + FP + FN = 0`)은 `N/A`로 표시하고 사례 수를 함께 제시한다. `N/A`를 0이나 1로 바꾸지 않는다.
- ROC-AUC는 한 레이블만 있으면 `N/A`다.
- seed 평균·표준편차는 3개 seed 모두 값이 있을 때만 계산하고, 하나라도 `N/A`면 seed별 값만 표시한다.
- 임계값 선택은 두 레이블이 모두 있는 `validation_clean`에서 위 F1 계산식을 쓰므로 모든 후보에서 F1이 정의된다.

**신뢰구간 산출 단위:**

1. 재표집 단위는 원문 그룹이다. 추가 평가 사례는 원문 그룹 ID 단위로 묶는다. 원본 test·validation 및 외부 자료는 제공된 원문/대화 그룹 ID가 있으면 이를 보존하고, 없으면 각 행을 하나의 그룹으로 둔다. 같은 평가 자료 안에서 정규화 키가 같은 행은 한 그룹으로 묶는다.
2. 두 레이블이 있는 평가셋은 그룹의 원문 레이블별로 층화해 재표집한다. 원문 레이블이 여러 개인 그룹은 혼합 레이블 층으로 따로 둔다. 검수에서 변형의 레이블이 원문과 달라진 그룹은 원문 레이블 층에 두고 사례 레이블로 지표를 계산한다.
3. 각 bootstrap 표본마다 비교하는 두 조건에 같은 그룹 표본을 쓰고, 각 조건의 지표를 seed별로 계산해 3-seed 평균을 낸 뒤 차이를 구한다. 2,000개 차이의 2.5%·97.5% 백분위를 95% 신뢰구간으로 보고한다.
4. 사전에 지정한 주요 비교는 A→B, A→C, A→D다. 그 밖의 비교(C→D, B→D, 기본 모델 간 비교)는 같은 방법으로 계산하되 보조 결과로 표시한다. 다중 비교 보정은 하지 않으므로 신뢰구간은 기술적 근거로 해석한다.

이 신뢰구간은 학습된 3개 모델을 고정한 상태에서 평가 원문 표집에 따른 불확실성만 나타낸다. 학습 seed 간 변동은 표준편차로 별도 보고한다. 같은 원문에서 파생한 변형을 독립 사례처럼 재표집하지 않으며, 작은 표본이나 단일 변형 조건의 작은 차이를 일반적인 개선으로 단정하지 않는다.

| EVAL-01 | 데이터 처리·모델·임계값·증강·평가 사례 생성 규칙 및 외부 출처·선별 규칙을 동결한 뒤(동결 1) test 파생·외부 자료를 생성/변환·검수한다. 최종 목록과 실제 수량을 고정한 뒤(동결 2) 예측한다. 3.2와 3.4의 절차를 따른다. | 두 동결 시점과 설정·출처·목록 버전 기록 |
| EVAL-02 | 세 기본 모델과 대표 모델 A~D를 전체 test·test_clean·최종 변형 사례·외부 출처별 자료에서 평가한다. 같은 유형의 새 사례·보류한 생성 방식·외부 출처를 분리 보고한다. | 조건별 공통 평가 목록과 평가군·출처별 결과표 |
| EVAL-03 | 최종 결과로 모델·임계값을 다시 선택하거나 학습을 반복하지 않는다. 이후 변경은 별도 실험으로 구분한다. | 개발 결과와 최종 결과의 사용 이력 |
| EVAL-04 | 변형 및 외부 자료의 탐지율·정상 오탐률·F1을 원본 성능과 함께 해석한다. 출처·레이블 비율·길이·언어·정책 차이를 구분하고 외부 지표로 재튜닝하지 않는다. | 내부·외부 개선과 성능 손해를 포함한 분석 |
| EVAL-05 | 개선 후에도 남은 오류와 평가 자료의 범위를 설명한다. | 잔여 실패 사례 및 적용 범위 |

연구의 개선 목표는 **변형 공격 탐지율을 높이면서 정상 입력 오탐률과 원본 성능의 손해를 줄이는 것**이다. 이는 검증할 목표이며 성능 향상을 보장하는 완료 조건은 아니다. 개선 효과가 없거나 지표 간 상충이 나타나도 사전에 정한 비교 실험과 분석을 완료하면 연구 결과로 보고한다.

## 8. 진행 단계와 완료 기준

| 순서 | 단계 | 완료 기준 |
| --- | --- | --- |
| 1 | 데이터 및 환경 준비 | 품질 점검·처리 규칙·분할 관리·GPU 시험 실행 확인 |
| 2 | 세 모델 파인튜닝 및 기본 비교 | 공통 조건의 실행별 결과, seed 평균·표준편차, 초기 오류 목록 |
| 3 | 추가 평가 및 취약점 분석 | 네 ROB 조건과 ROB-01 하위 유형의 개발 결과, 원문 수와 검수 기록, 대표 모델 선정 |
| 4 | 개선 실험 및 설계 동결(동결 1) | A~D 개발 결과, 최종 모델·임계값·증강·test_clean·추출/생성 규칙과 외부 출처·revision·선별/중복 규칙 고정 |
| 5 | 최종 평가 자료 고정(동결 2) 및 검증 | test 파생·외부 자료 검수와 목록/수량 고정 후 원본·변형·외부 Robustness 결과, 신뢰구간·출처별 오류 분석 |
| 6 | 보고 및 시연 | 보고서·발표 자료·재현 절차·시연 도구 준비 |

필수 최소 구성은 세 모델 × 공통 seed 3개, 네 ROB 조건(ROB-01은 하위 유형 분리), 대표 모델 A~D 비교, 3.4의 기본 목표에 맞는 외부 출처별 Robustness 평가다. 본실험 학습은 기본 모델 9회와 대표 모델 증강 3회로 **총 12회**이며, A/B 및 C/D는 각각 체크포인트를 공유한다. 시험 실행·재실행·추가 탐색 비용은 별도로 기록한다. 평가 사례는 앞의 독립 원문 50개 목표를 기준으로 하고, 100개로 확대하거나 실제 LLM 연결 실험을 추가하는 것은 확장 범위다.

실제 주차별 일정과 설계·최종 평가 목록 동결일은 제출 마감과 팀 일정 확인 후 역산해 정한다. 동결 전까지 개발과 개선을 완료하고, 동결 후에는 test 결과에 따른 설계 변경을 하지 않는다.

최종 산출물 체크리스트:

- [ ] 데이터 품질 점검 및 처리 이력
- [ ] 세 모델의 학습 설정·체크포인트·기본 비교 결과
- [ ] 추가 평가 사례와 생성·검수·분할 기록
- [ ] 모델별 오류·취약점 분석
- [ ] 대표 모델의 A~D 비교 결과 및 최종 설정
- [ ] 최종 평가 결과표·그래프·잔여 실패 사례
- [ ] 외부 데이터 출처·레이블 대응·revision·중복 점검 및 출처별 Robustness 결과
- [ ] 입력 및 변형 비교 시연 도구
- [ ] 재현 절차·최종 보고서·발표 자료

## 9. 실험 전에 추가로 확정할 사항

- 조교 확인이 필요한 제출 형식·마감·공식 test 사용 규칙과 숨겨진 평가셋 여부
- 유사 문장 점검 방법·기준 및 상충 레이블의 실제 검수 결과
- 개발용 사례의 유형별 실제 원문 수, 검수 담당·모호한 사례 처리 기준 (최종용 실제 수량은 동결 2에서 확정)
- 용도별 문맥·주제·의역 프롬프트 목록과 증강에서 보류할 생성 방식
- 외부 후보의 이용 조건·접근성·최종 채택 분할·revision, 영어 선별·레이블 대응·출처 간 중복 처리
- 학습용 증강 규모와 공격·정상 사례의 구성 비율
- 시험 실행 후 최종 학습·환경 설정(배치·정밀도·학습률 스케줄)과 seed 초기값의 동결
- 정규화 키 일치 사례를 유사 문장 검수에서 제외할지 여부
- 팀 역할 분담, 주차별 일정, 설계 및 최종 평가 목록 동결일
- 선택 실험 수행 여부와 보호 대상 LLM·작업·성공 판정 기준

대표 모델 선정, 임계값 최적화, 총 학습 예산, 반복 및 통계 비교는 본문의 기본 규칙을 적용한다. 이를 변경할 때는 test 원문 추출 전 변경 사유와 적용 범위를 기록하고 비교 조건 전체에 동일하게 적용한다.
