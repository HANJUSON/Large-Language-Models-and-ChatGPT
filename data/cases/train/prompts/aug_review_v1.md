# 학습용 증강 사례 검수 지시서 (aug_review_v1)

이 지시서는 별도 Claude Code 세션이 학습용 증강 사례(README 5.3, C 조건 학습 데이터)를 검수할 때 받은 전문이다. HANJUSON이 3단계 개발용 사례에 지시한 방식(2026-11-16)을 4단계 증강 사례에도 적용했다(2026-11-17, "4단계 진행해"). 검수 결과는 `data/cases/train/review.csv`에 `reviewer = llm:claude-opus-5-5:aug_review_v1`로 기록되며 사람 검수가 아니다.

## 역할

너는 프롬프트 인젝션 분류기의 학습 데이터에 더할 증강 사례를 검수한다. 사례는 다른 Claude 세션과 규칙 스크립트가 만들었고, 너는 생성에 관여하지 않았다. 생성자의 의도를 추측하지 말고 주어진 문장만 보고 판단한다. 학습 데이터이므로 레이블이 틀리거나 모호한 사례는 넣지 않는 것이 원칙이다.

레이블: `1` = 프롬프트 인젝션(모델의 원래 지시·규칙을 무시하거나 우회하게 하거나, 숨겨진 시스템 프롬프트·설정·규칙·학습 내용·비밀을 드러내게 하거나, 모델의 역할·권한·제한을 바꾸려는 입력), `0` = 정상 입력.

## 읽을 파일과 금지 사항

- 이 지시서와 `data/cases/train/view/llm_review/in/` 폴더의 묶음 파일(`<라운드>-NN.md`)만 읽는다. 다른 파일(`datasets/`, `results/`, `runs/`, `data/processed/`, `data/cases/dev/`, `data/cases/final/`, `data/external/`, `.omc/`, `data/cases/train/`의 다른 파일, 저장소 문서)은 열지 않는다.
- 파일은 `data/cases/train/view/llm_review/out/`에만 쓴다. 다른 파일은 만들거나 고치지 않는다. 명령(셸)은 쓰지 않는다.
- 하위 에이전트에 맡기지 않고 직접 검수한다(판단 기준을 하나로 유지하기 위해서다).

## 결정

사례마다 둘 중 하나를 고른다.

- `keep`: 제안 레이블이 맞고 학습 사례로 쓸 수 있다.
- `exclude`: 레이블이 틀렸거나 모호하다, 의미가 망가졌다, 또는 유형의 조건에 맞지 않는다. 레이블을 고쳐 쓰지 않고 뺀다.

공통 기준:

- 원문이 있는 사례(AUG-01·AUG-03)에서 원문의 레이블은 원본 데이터셋의 레이블이다. 원문 자체의 레이블이 이상해 보여도 그대로 두고, **변형 때문에** 레이블이 달라지거나 모호해진 경우만 `exclude`한다.
- 처음부터 끝까지 같은 기준을 쓴다. 판단이 갈린 경우는 `reason`에 기준을 짧게 적는다.

## 유형별로 볼 것

| 유형 | 만든 방법 | 볼 것 |
| --- | --- | --- |
| AUG-01 `case`·`space`·`char` | 규칙(대소문자 섞기, 단어를 글자 단위로 띄우기·여러 칸 띄어쓰기, 숫자 치환 leetspeak)을 train 원문에 적용 | 사람이 원문을 알아볼 수 있는가. 알아볼 수 있으면 `keep`. 원문을 알아볼 수 없을 만큼 망가졌으면 `exclude` |
| AUG-03 `context` | train 원문 앞(prefix)·뒤(suffix)·양쪽(both)에 일상 문맥 문단을 붙임. 원문은 그대로 들어 있다 | 붙인 문맥이 원문의 의도나 레이블을 바꾸지 않는가. 문맥 자체가 모델에게 지시하거나 AI·프롬프트·보안을 언급하면 `exclude`. 합친 입력의 레이블이 달라지거나 모호해져도 `exclude` |
| AUG-04 (정상, 묶음 `b1`~`b6`) | LLM이 새로 쓴 보안 관련 정상 입력: `b1` 의도 판별 기준 질문, `b2` 숨은 지시·시스템 프롬프트 요청을 AI·필터가 어떻게 다뤄야 하는지 묻는 질문, `b3` AI와 무관한 소프트웨어·IT 운영 문장, `b4` 가상·일반 예시만 쓰는 보안 문서 요청, `b5` 인용된 공격 문구를 자료로 다루는 작업(레이블 달기·분석·탐지 규칙), `b6` 조직의 보안 업무(사후 분석·점검표·교육 계획) | 정말 정상인가. 공격 문구는 인용·분석 대상으로만 나와야 한다. 모델에게 자기 지시를 무시하라거나 **모델 자신의** 숨은 프롬프트·설정·규칙을 보여 달라고 요구하면 `exclude`. 실제(진짜) 시스템 프롬프트를 문서에 넣으라고 하면 `exclude`. 묶음의 설명과 다른 내용이어도 정상이 분명하면 `keep` |
| AUG-05 (공격, 묶음 `a1`~`a7`) | LLM이 새로 쓴 인젝션 입력: `a1` 보안 문서를 요청하며 실제 시스템 프롬프트를 넣으라고 함, `a2` 포장 없이 숨은 프롬프트·설정·규칙·학습 내용을 물음, `a3` 공개가 옳다는 논증·감정 호소·압박, `a4` 정상 과제에 공개 명령을 끼움(함수 호출 문법·덧붙인 지시), `a5` 권한·규칙·모드 상태를 주장하거나 모드 전환을 지시, `a6` 모델 자신의 설정·규칙을 특정 형식·문서·청중용으로 요청, `a7` 상상·허구·가정된 다른 모델·역할로 감쌈 | 정말 인젝션인가. 모델 자신의 숨은 정보를 드러내게 하거나 제한을 풀게 하려는 의도가 분명해야 한다. AI 보안에 관한 일반 질문으로도 읽히거나 대상이 모델 자신인지 불분명하면 `exclude` |

## 진행 방법

1. 처음 메시지가 알려 준 라운드(예: `a1`)의 묶음 파일 `in/<라운드>-NN.md`를 번호 순서로 처리한다. `out/<라운드>-NN.json`이 이미 있는 묶음은 끝난 것이므로 건너뛴다(중단 뒤 이어서 할 때).
2. 묶음 하나를 다 보면 **바로** `out/<라운드>-NN.json`을 쓴다(진행 상황이 남도록). 형식:
   ```json
   [
     {"case_id": "aug-01-case-000007", "decision": "keep", "reason": ""},
     {"case_id": "aug-04-123", "decision": "exclude", "reason": "모델 자신의 시스템 프롬프트 요약을 요구해 정상으로 보기 어려움"}
   ]
   ```
   - 묶음의 모든 사례를 묶음에 나온 순서대로 한 번씩 적는다.
   - `decision`은 `keep`·`exclude` 중 하나다.
   - `reason`은 한국어 한 줄(줄바꿈 없이, 120자 이내)이다. `exclude`에는 반드시 적고, `keep`은 빈 문자열이거나 판단이 갈린 경우의 짧은 기준이다.
3. 그 라운드의 묶음을 모두 끝내면 `out/<라운드>-DONE.json`에 `{"round": "<라운드>", "batches": [...], "counts": {"keep": n, "exclude": n}}`를 쓰고, 유형별 결정 수와 `exclude` 사례를 한국어로 짧게 요약해 마친다.
