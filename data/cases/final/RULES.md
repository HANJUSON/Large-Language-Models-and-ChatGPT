# 최종 평가 사례 규칙 (동결 1에서 고정, 2026-11-17)

5단계에서 만들 최종 평가 사례(README 5.2 ROB-01~04, 3.2 test 사용 절차)의 추출·생성·검수·대체 규칙이다. 동결 1 이후에는 바꾸지 않는다. 이 문서와 `final_spec.json`, `prompts/`의 프롬프트 세 개, 규칙 변형 코드(`scripts/build_dev_cases.py`의 `rob01-v1` 함수와 `assemble`·`plan_rob03`)의 SHA-256을 `freeze/freeze-1.json`에 기록한다. 사례를 만드는 실행 스크립트는 5단계에서 이 규칙대로 작성한다(동결 뒤에 쓰는 코드이므로 이 문서와 다르게 동작하면 안 되고, 다르면 이 문서가 우선한다).

동결 1 전에는 test 원문을 열지 않았다. 아래 규칙은 개발용 사례(3단계)의 규칙을 그대로 옮기고, 원문 출처·seed·LLM 프롬프트 목록만 최종용으로 바꾼 것이다.

## 1. 수량

| 조건 | 공격 원문 | 정상 원문 | 원문당 사례 | 평가군 |
| --- | ---: | ---: | --- | --- |
| ROB-01 | 50 | 50 | `case`·`space`·`char`·`homoglyph` 각 1개(원문당 4개) | `case`·`space`·`char`는 `main`(증강 AUG-01과 같은 연산), `homoglyph`는 `held_out`(증강에 쓰지 않은 방식) |
| ROB-02 | 50 | 50 | 의역 1개 | `main` (대응하는 증강 유형 없음) |
| ROB-03 | 50 | 50 | 문맥 추가 1개 | `main` (증강 AUG-03과 같은 틀, 다른 문맥 문단) |
| ROB-04 | 0 | 50 | 새 정상 입력 | `main` (원문 없음) |

- 예비: 레이블별 원문 15개(ROB-01~03 공용), ROB-04는 LLM 항목 51~65번.
- 검수 대상은 650건(ROB-01 400, ROB-02 100, ROB-03 100, ROB-04 50)이다. 실제 수량은 검수와 대체를 마친 뒤 동결 2에서 확정한다. 대체 후에도 목표에 못 미친 조건은 실제 수량과 이유를 적고 탐색적 결과로 보고한다(README 5.2).

## 2. 원문 추출

- 후보: 동결 1의 `data/processed/test_clean.csv`(최종 `test_clean`). 레이블은 test.csv의 값이다.
- 레이블별(1, 0 순)로 후보의 문장 ID를 정렬한 뒤 `random.Random(f"s5-final:20261117:label{label}")`로 한 번 섞는다. 앞에서부터 0~49번을 ROB-01, 50~99번을 ROB-02, 100~149번을 ROB-03, 150~164번을 예비로 배정한다. 사람이 원문을 고르거나 바꾸지 않는다.
- 원문 그룹 ID는 test 문장 ID(`test:NNNNNN`)다. ROB-04는 사례 ID가 그룹 ID다.

## 3. 생성

- ROB-01 (규칙 `rob01-v1`): `scripts/build_dev_cases.py`의 `ROB01[subtype](text, random.Random(f"rob01-v1:{case_id}"))`. 사례 ID는 `final-rob01-<subtype>-<test 행 번호 6자리>`. 네 방식 모두 같은 원문에 적용한다. 결과가 `None`(바꿀 글자 없음)이면 그 원문 그룹 전체를 제외하고 대체한다.
- ROB-02 (LLM): 프롬프트 `prompts/rob02_paraphrase_final_v1.md`. ROB-02와 예비 원문 130개를 주고 의역 하나씩 받는다. 사례 ID는 `final-rob02-<행 번호>`.
- ROB-03 (템플릿 `rob03-v1` + LLM 문맥): 프롬프트 `prompts/rob03_contexts_final_v1.md`로 문맥 문단 120개(짧은 것 80, 긴 것 40)를 받는다. `plan_rob03`(seed 문자열 `rob03-v1`)로 i번째 공격 원문과 i번째 정상 원문에 같은 문맥을 배정하고 `assemble`로 앞(`prefix`)·뒤(`suffix`)·양쪽(`both`)에 빈 줄을 두고 붙인다. 세 토크나이저 모두 특수 토큰을 포함해 256토큰 이내이고 원문이 그대로 들어 있어야 한다. 사례 ID는 `final-rob03-<행 번호>`.
- ROB-04 (LLM): 프롬프트 `prompts/rob04_benign_final_v1.md`로 정상 입력 65개를 받는다. 사례 ID는 `final-rob04-<3자리 번호>`.
- LLM: Claude `claude-opus-5-5`(개발용 사례와 같은 모델, Claude Code 하위 에이전트). 학습용 증강 문장을 만든 모델(`claude-fable-5-2`)과 다른 모델을 써서, 증강 문장과 평가 문장의 문체가 같은 생성기에서 나오지 않게 한다. 이 모델을 쓸 수 없게 되면 대체 모델과 사유를 동결 2 전에 기록한다. 받은 출력은 `data/cases/final/llm/`에 모델·프롬프트 SHA-256·날짜와 함께 저장하고, 그 파일이 기록이다. LLM에는 해당 프롬프트와 필요한 원문(ROB-02만)만 준다. 모델 예측, 개발용·증강용 문장은 주지 않는다.
- 최종용 프롬프트의 문맥 종류 10개는 개발용·증강용 목록과 겹치지 않는다(DATA-07). ROB-04의 범주 8개는 개발용과 같다(같은 대상을 재기 위해서다). 항목은 새로 만들고 아래 자동 점검으로 개발용·증강용 문장과의 중복을 뺀다. 최종용 프롬프트에는 ASCII 문자만 쓰라는 규칙을 더했다(개발용 문맥 한 개에 비ASCII 문자가 들어가 모델이 반응할 수 있었다).

## 4. 자동 점검 (검수 전)

사례 문장이 아래에 해당하면 그 원문 그룹을 제외하고 같은 레이블의 다음 예비 원문으로 대체한다(ROB-04는 다음 예비 항목). 제외 사유와 대체 이력을 기록한다.

1. 정제 train·증강 사례(`data/cases/train/train_aug.csv`의 사례)·validation 전체의 문장과 완전 중복 키가 같다(README 3.2 3번).
2. 증강 사례 또는 개발용 사례(`data/cases/dev/cases.csv`와 개발용 LLM 출력)와 완전 중복·정규화 키·구두점 키가 같다. ROB-04는 train·validation 문장과 정규화 키·구두점 키가 같아도 제외한다(개발용과 같은 규칙). ROB-04와 ROB-02는 증강·개발용 문장과 단어 하나만 달라도 제외한다.
3. 최종 사례끼리 문장이 같다.
4. ROB-02: 의역이 원문과 구두점 키가 같거나 단어 하나만 다르다.
5. ROB-03: 256토큰을 넘거나 원문이 그대로 들어 있지 않다. 맞는 문맥이 없으면 그 원문을 제외한다.
6. ROB-04: 40~200자를 벗어나거나 줄바꿈이 있다. LLM 문장(ROB-02·03·04)에 비ASCII 문자가 있다.

ROB-01~03 사례가 train·validation 문장과 정규화 키·구두점 키로만 일치하면 제외하지 않고 표시한다(개발용과 같다).

## 5. 검수와 대체

- 검수 기준은 개발용과 같다(`data/cases/dev/REVIEW_GUIDE.md`): `keep`(레이블이 맞고 쓸 수 있음), `relabel`(변형 때문에 레이블이 바뀜, ROB-04는 쓰지 않음), `exclude`(의미가 망가졌거나 의도가 모호함). 원문의 레이블은 test.csv의 값을 기준으로 두고, 변형 때문에 레이블이 바뀐 경우만 `relabel`한다. 검수는 모델 예측을 보지 않고 한다.
- 검수자: HANJUSON, 또는 HANJUSON이 지시한 별도 Claude Code 세션. 세션이 검수하면 `llm:<모델>:<지시서 버전>`으로 적고 사람 검수가 아님을 README에 적는다(3·4단계와 같은 방식). 생성에 쓴 세션과 맥락을 공유하지 않고, 사례 문장과 원문만 보여 준다.
- `exclude`한 원문 그룹은 모든 사례(ROB-01은 네 방식 모두)를 같은 레이블의 다음 예비 원문으로 대체하고, 새 사례를 다시 검수한다.
- 검수·대체가 끝난 목록의 경로·SHA-256·실제 수량을 `freeze/freeze-2.json`에 기록한 뒤(동결 2) 예측을 한 번 실행한다.

## 6. 평가에 쓰는 고정값

- 모델: 세 기본 모델(2단계 9개 실행)과 대표 모델 RoBERTa의 A~D(`freeze/freeze-1.json`의 체크포인트 SHA-256과 seed별 임계값).
- 판정 규칙과 기준값은 README 1.1, 신뢰구간은 README 6.1이다. 보조 결과로 정상 사례 FPR 변화(ROB-01 정상 변형, ROB-04)를 README 5.3의 규칙으로 함께 보고한다.
